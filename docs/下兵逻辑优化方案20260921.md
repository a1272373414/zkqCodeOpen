## 二、源项目下兵架构（可复用资产）

来源文件 `awcocx_main.lua`，关键函数与行号：

### 2.1 战场被切成 4 象限
每个象限维护一组坐标：`开始X/Y`、`结束X/Y`、`中间X/Y`、`总长`，以及"走行/偏移"量。

竖屏基准点（L36500 附近）：
```
左上开始X/Y = 580, 507     右上开始X/Y = 580, 763
左下开始X/Y = 413, 237     右下开始X/Y = 413, 1029
```
- 之后按 `缩进直`、`右上走行`、`左上走行` 等做微调（L24822、L36520+）。
- `结束X = 开始X - 200 + 走行...`，`中间 = (开始+结束)/2`。
- **`XY差值 = 1.334134615384615`**（L2247）：竖屏下"横向 1 像素 ≈ 纵向 1.334 像素"的换算系数，源里所有 `xxx * _ENV["XY差值"]` 都靠它。
  → 迁到横屏 1280×720 时，这个系数与象限基准点都必须**重新标定**（不能照抄）。

### 2.2 下兵方式（`下兵方式`）四选一
来自配置（L73980 附近）：
- `四面`：上下两面各放一批（`放兵("上")` + `函数132a()` + `放兵("下")`，L36624）
- `单面仿滑屏`：单面、用 `函数327a` 模拟滑屏
- `单面真滑屏`：单面、用**双指 `touchDown/touchMoveEx` 真滑屏**（L36662+，数量 > 14 时启用）
- `单面中间单点下兵`：`单面中间单点下兵(位置, 兵x, 兵y, 数量)`（L36830），在象限中心单点连点

### 2.3 `援兵位置`（左上 / 右上 / 左下 / 右下）
决定援兵与主力的落点象限（L36632、36638）。

### 2.4 主放兵入口 `放兵(上下)`（L36872）
顺序：
1. **先下法术**：`下法术==true` 时，按 `findMultiColor` 逐个找法术图标（地震 `5A8ABD`、弹跳 `09D453`、狂暴…），找到即 `taps` 选法术 → `函数327a(上下, 数量, 类型)`。
2. **再下部队**：对每个兵种调 `函数142a(上下, 兵种, 数量, 色头, 色值)`。

### 2.5 `函数142a(上下, 兵种, 数量, 色头, 色值)`（L36650）
- `四面 / 单面仿滑屏` → 直接 `函数327a(上下, 数量, 兵种)`。
- `单面真滑屏`：
  - 数量 > 14 → **双指** `touchDown(1,..)/touchDown(2,..)` + 循环 `touchMoveEx(...)` 横扫（L36672+）。
  - 数量 ≤ 14 → 仍走 `函数327a`。

### 2.6 `函数327a(上下, 兵数, 放兵类型, 波)`（L37754）
- 按 **放兵类型** 给四象限设置 `偏移X/Y`（不同兵种/法术落点内缩量不同），例如：
  - 法术 `-30`、骷髅/蝙蝠 `-80`、弹跳 `-73`、地震 `-60`、冰冻 `-95`、隐形 `-50`、镜像 `-30`、蔓生 `-100`、毒药 `-130`、雷电/愤怒/图腾/炸弹 各有值（L37768–L37900）。
  - 偏移 = `-N`（X） 且 `+N * XY差值`（Y），把落点从象限"开始线"沿对角线内收。
- 支持 **波次 `波`=1..4+**（L37906）：每波额外 `a * XY差值` 的 Y 偏移，形成多波推进（L37924–37940）。

### 2.7 `放兵速度`
全局配置 `放兵速度`（默认 25，下限 15，L107143 / L109116），控制连点间隔；代码里大量 `sleep(_ENV["放兵速度"] + math.random(0,5))` 做随机化拟人。

### 2.8 夜世界：靠"夜世界王"定位（L31916）
```
夜世界王X, 夜世界王Y = findMultiColor(48, 15, 142, 500, "3067A2", "...", 0, 0.9)
if 夜世界王X > -1 then taps(夜世界王X, 夜世界王Y) end   -- 选中并下机器
```
即夜世界不是"扫整条部署栏"，而是**用战争机器的专属色特征在部署栏区域精确定位后点选**；技能释放另用 `FFB2FF`/`FE3AC7` 特征（L33272）。

### 2.9 都城：`函数31a` 残血点驱动放兵（L8403）
- 先识别"下兵点/放弃按钮"，统计特征数量决定是否可以开始放兵（L8413、8461）。
- 对每个 `都城下兵_*` 兵种：`函数26a(特征)` 命中 → `taps` 选兵 → 循环：遍历 `特征["残血"]`（L7505，低血敌人标记）找到就 `taps(下兵点)`（L8837–8960）。
- 法术（疗伤/弹跳/骷髅）单独走"选法术 → 找残血点 → 落法术"（L8879+，L94989+）。
- `偷袭法术下兵点`（L5977）/`偷袭冰冻法术下兵点`（L6841）为法术溅射点特征。

### 2.10 都城下兵特征格式（可直接转换）
`特征` 表（L5737–5977），格式 = `{x1,y1,x2,y2, 主色, 偏移串, 方向, 相似度}`：
```lua
["都城下兵_超级矿工"] = { 4, 28, 135, 1220, "7C9FEB",
  "-7|0|174B79|-8|-7|325C88|...", 0, 0.9 }
```
共 12 条：超级矿工、野猪偷袭队、超级巨人、超级法师、隐秘弓箭手、超级野蛮人、野蛮人攻城槌、骷髅法术、疗伤法术、雷电法术、弹跳法术、冰冻法术。
→ 与 `ColorSchema.parse(x1,y1,x2,y2,"主色","dx|dy|色,..",dir,sim,name)` 一一对应（仅分隔符 + 90° 旋转差异，见 §五）。

## 四、优化方案

### 4.0 新增通用基础设施（三模式共用）

建议新增目录 `app/src/main/java/com/coc/zkqcode/jar/code/universal/deploy/`：

1. **`DeployGeometry.kt`** —— 四象限几何
   - 把源竖屏基准点经 90° 旋转映射到 1280×720，并**用真机截图校准**出本项目自己的 `左上/右上/左下/右下` 基准点与 `XY差值`。
   - 提供 `quadrantStart/End/Middle(位置)`、`applyOffset(位置, dx, dy)`、`sweepLine(位置)`。
2. **`DeployStrategy.kt`**（枚举 `下兵方式`：`四面 / 单面仿滑屏 / 单面真滑屏 / 单面中间单点`）+ **`援兵位置`** + **`放兵速度`**（读 `Schema` 配置，默认 25，下限 15）。
3. **`DeployUnit.kt`** —— 统一部署单元：`特征 schema + 兵种名 + 数量来源 + 放兵类型(法术/骷髅/蝙蝠/弹跳/地震/冰冻/隐形/镜像/蔓生/毒药/雷电/愤怒/图腾/炸弹) + 波次`。
4. **`DeployExecutor.kt`** —— 执行器：
   - `函数327a` 等价：按类型设偏移、按波次推进、沿象限线连点。
   - `函数142a` 等价：数量 > 14 走**双指真滑屏**（复用 `TouchActions.touchDown/touchMove`，id=1、2），否则走按类型定向放兵。
   - 所有间隔套 `放兵速度 ± random` 拟人化（已有 `delayWithMultiplier`）。
5. **部署栏识别增强**：在"类别色"之外补**具体兵种色特征**（主世界/夜世界各自一份），并补"数量 `xN`"读取（复用 `PixelFontOcr`，见 `CapitalArmyTraining`）。

### 4.1 主世界（改造 `MainBaseDeployTroops.kt`）

**目标**：把"固定拖拽"升级为源同款"四象限 + 波次 + 数量感知"。

1. 用 `DeployExecutor` 取代 `dragUntilDeployed` 里的硬编码 `(600,50)/(85,430)`：
   - `下兵方式` 默认 `四面`：`放兵("上")`（左上+右上象限）→ 清场 `函数132a` → `放兵("下")`（左下+右下）。
2. `deployOthers()` 保留类别色做**兜底**，但优先用具体兵种 schema；命中后按 `函数327a` 的"类型偏移"落到对应象限，而不是写死 `(310,247)`。
3. 法术独立走"先选法术图标（`findMultiColor` + 类型）→ 按类型偏移落点"，支持 `ReviveSpellAtDeploymentBar` 等。
4. 数量 > 14 的兵种（如野蛮人/弓箭手）启用**双指真滑屏**。
5. 落点坐标不写死：全部由 `DeployGeometry` 用本项目标定值计算（源基准点仅作起点参考）。

### 4.2 夜世界（改造 `normalBattle()`）

1. **新增 `夜世界王` 特征**（源 `3067A2`，区域 48,15,142,500 竖屏 → 90° 旋转 + 校准到横屏），用 `findMultiColors` 在部署栏**精确定位战争机器**，替换写死的 `tap(125,610)`。
2. 用 `tools/_bb_deploy.png` 派生**部署栏各兵种色特征**，写入 `BuilderBaseAttackColors.kt`，让 `normalBattle` 能按兵种放兵（而非只分"女巫/野蛮人"）。
   - 先修 `tools/_crop_bb.py` / `_an.py` 的槽位坐标（当前 y 取到草地，见 §六）。
3. 保留"女巫流技能连点"与"野蛮人流游走"两条现有分支，但落点改由 `DeployGeometry` 提供（4 象限）。
4. 机器/部队落点不再用 `deployPositions` 硬编码表，改为象限随机点。

### 4.3 都城（新建下兵链路）

1. **新建 `app/.../clancapital/attack/CapitalAttack.kt`**，移植源 `函数31a`：
   - 识别"下兵点/放弃按钮" → 统计特征数达标 → 开始放兵。
   - 遍历 `都城下兵_*`（12 兵种）→ 命中选兵 → 遍历 `残血` 特征找目标点 → `tap` 放兵。
   - 法术（疗伤/弹跳/骷髅/雷电/冰冻）走"选法术 → 残血/偷袭点溅射"。
2. **特征迁移**：把 `awcocx_main.lua` L5737–5977（12 兵种+法术）、L5977/L6841（偷袭法术点）、L7505（`残血`）按 90° 旋转 + 分隔符转换，生成 `colorpackage/clancapital/CapitalDeployColors.kt`（`ICapitalDeployColors`）。
   - 转换脚本可复用 `tools/migrate_lua_colors.py`（已内置 11.3 映射）。
3. **接入流程**：`SceneState.CLAN_CAPITAL` 识别到都城后，接到 `CapitalAttack`（入口→目标→开打→下兵→回营）。填补 `clanCapitalTutorial()` 空实现。
4. 都城配兵 `trainCapitalArmy()` 接入攻打链路（当前无调用者）。

## 五、坐标与特征迁移规范

沿用 `复用优化方案20260919.md` §11.3（已验证）：
```
区域 (x1,y1,x2,y2) → (y1, 719-x2, y2, 719-x1)    # 取 min/max 并 clamp 1280×720
偏移 (dx,dy)       → (dy, -dx)
```
- 分隔符：源"点间 `|`、点内 `|`" → 本项目"点间 `,`、点内 `|`"（内含 `-101010` 后缀可保留或剥离，`ColorSchema.parse` 会忽略 `-` 之后内容）。
- ~~**注意**：`XY差值 = 1.334` 与四象限基准点是**竖屏专属**，横屏必须重新标定，不能照抄。~~
  **⚠️ 该结论已作废（2026-09-22 实测纠正）**：源脚本自带分辨率守卫
  `请把分辨率设置竖屏：720*1280-dpi：320`，而本项目运行在同一块屏的横屏态 1280×720 —— 两者是
  **同一矩形转 90°，像素 1:1**，`taps` 就是 `touchDown(0,x±1,y±1)+touchUp(0)` 无缩放。
  因此象限基准点与 `XY差值 = 1.334134615384615` **照搬即可**（`XY差值` 是基地菱形边的斜率，
  与屏幕方向无关）。换算只有一条：`realX = srcY`、`realY = 720 - srcX`（见 §九）。

## 六、已知坑与验证

1. **部署栏大小**：源多处提示"游戏设置-部署栏大小用默认大小"（L27474、L95619）——非默认大小会破坏所有落点与特征，需在方案中显式检查/提示。
2. **`_bb` 分析工具的 bug**（2026-09-22 已清理临时脚本，结论保留）：`_crop_bb.py` / `_an.py` 取槽位 `y=514..582` 是错的，实测夜世界部署栏卡片在 **`y≈575..700`**，取 `y=514..582` 会采样到草地（`375350` 等绿色）。开发夜世界（M3）时按 `y≈575..700` 重新切槽位；夜世界部署栏截图已归档为 `tools/captures/builderbase/bb_deploy.png`。
3. **离线受阻项**：文档 11.11 记录部署栏截图曾受阻；现已具备 `tools/captures/attack/live_bar_b1.png`（主世界）与 `tools/captures/builderbase/bb_deploy.png`（夜世界）。
4. **行为改动需真机验证**：源坐标旋转后对现版本是否仍适用，必须用 `emulator-5556` 实跑校准（参照 §11.3 的做法：多张截图交叉命中）。
5. **法术数量**：主世界当前造兵计划是"闪电法术 × 8"（文档 11.14 ⑥），下兵侧需与造兵计划对齐。

### 9.1 关键纠正：坐标是 1:1 旋转，无需重新标定

源脚本自带分辨率守卫 `请把分辨率设置竖屏：720*1280-dpi：320`，`taps` 就是
`touchDown(0,x±1,y±1)+touchUp(0)`（无缩放包装）。本项目运行在同一块屏的横屏态 1280×720，
所以两者是**同一矩形转 90°，像素 1:1**：

```
realX = srcY
realY = 720 - srcX
```

→ 本文档 §二.1 的象限基准点与 `XY差值 = 1.334134615384615` **照搬即可**
（`XY差值` 是基地菱形边的斜率，与屏幕方向无关）。§五里"必须重新标定"的结论作废。

### 9.9 网络异常（中央橙色转圈）判定规则

- 口径：画面**正中央的橙色转圈**= 网络异常（连接卡死），不是加载动画、也不是"选中建筑"的光环；
  持续存在且 12 秒内画面无变化 → **重启游戏**。
- 实现：`universal/smalltools/CheckReconnections.kt`
  - `detectStuckNetworkSpinner()`：区域 `x∈[400,880], y∈[250,500]`，橙色口径 `R>200 && G∈[80,185] && B<120`，
    橙像素 ≥300 起判；每 2s 采样，帧差 >200 视为"仍在动"；满足则 `killGame()` + `runGame()`；
  - 调用点：`checkReconnections()` 开头（所有等待循环统一入口）。
